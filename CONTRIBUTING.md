# Contributing to Awesome Decentralized Web

Thanks for helping keep this list useful for people building and studying the decentralized web. Contributions should improve the quality of the curated README and stay focused on protocols, applications, and resources for decentralized, peer-to-peer, federated, local-first, or user-owned web technologies.

## What Fits

Good additions usually meet these criteria:

- The project is open source, actively useful, or historically important to decentralized web work.
- The entry belongs in one existing section, such as protocols, applications, storage, media, social networking, web, or related lists.
- The description is short, factual, and explains why the resource matters.
- The link points to the project's official site, repository, specification, or documentation.
- Discontinued projects are clearly marked when they remain relevant as historical references.

Please do not submit pseudo-currencies, crypto coins, NFTs, DAOs, finance projects, or promotional listings. The README already keeps that boundary so the list stays focused on decentralized web technology rather than speculation or marketing.

## Entry Format

Use the existing bullet style:

```markdown
* [Project Name](https://example.com/) - Short factual description.
```

Keep descriptions concise and neutral. Avoid hype, affiliate links, tracking URLs, referral codes, and duplicate resources already listed in the README.

## Before Opening a Pull Request

1. Search the README to make sure the resource is not already listed.
2. Check that the link works and points to the best canonical source.
3. Place the entry in the most specific matching section.
4. Keep entries alphabetized when the surrounding section is already alphabetized.
5. Run a Markdown preview or linter if you have one available.

## Pull Request Guidelines

- Use one focused pull request for one resource or a small related group of resources.
- Explain why the resource belongs in the list.
- Mention whether the project is discontinued, archived, experimental, or maintained.
- Keep unrelated formatting changes out of the same pull request.

Maintainers may ask for a different section, a shorter description, or removal of resources that do not match the scope above.
